# 개발 연동 기록

> 기준일: 2026-09-10
> 범위: 로컬 Anvil, 컨트랙트 배포, 프론트엔드·백엔드 연동

## CRB-INT-001 — 로컬 배포 후 거래 가능한 데모 상태 부족

- 상태: 해결
- 영향: 프론트엔드가 배포 직후 실제 투자·정산 흐름을 실행할 수 없었음
- 원인: 기존 배포 스크립트가 투자자에게만 mUSD를 지급하고 상품을 생성하지 않았음
- 처리: 별도 크리에이터 주소, 정산자 mUSD 잔액과 모집 중인 데모 상품 초기화 추가
- 검증: 배포 테스트와 Docker Anvil 상태 조회로 역할·잔액·상품 조건 확인

## CRB-INT-002 — 배포 주소와 ABI의 애플리케이션 공유 방식 부재

- 상태: 해결
- 영향: 프론트엔드에 하드코딩한 주소가 실제 배포 주소와 달라질 수 있음
- 처리: 로컬 배포 manifest 생성과 세 컨트랙트 ABI 추출을 하나의 명령으로 자동화
- 산출물: 프론트엔드와 백엔드의 생성 전용 컨트랙트 디렉터리에 동일한 주소·ABI 복사
- 후속 작업: 각 애플리케이션의 기존 하드코딩 설정을 생성 산출물 참조 방식으로 전환

## CRB-INT-003 — 프론트엔드 상품 상태와 컨트랙트 enum 불일치

- 상태: 해결
- 영향: 프론트엔드가 `Failed`, `Settling`, `Closed` 상태를 구분하지 못했음
- 처리: 컨트랙트 enum 값과 화면 표시 이름을 연결하는 공용 클라이언트 metadata 추가
- 추가 구성: 주요 custom error와 사용자 안내 메시지 매핑을 같은 metadata에 포함
- 검증: Foundry 테스트에서 여섯 개 상태 코드가 컨트랙트 enum 값과 일치하는지 확인

## CRB-INT-004 — 실제 RPC 전체 정상 흐름 자동화 부재

- 상태: 해결
- 영향: 애플리케이션 개발자가 역할별 호출 순서와 최종 잔액을 수동으로 검증해야 했음
- 처리: 새 데모 배포부터 투자·정산·종료·종료 후 청구까지 실행하는 단일 명령 추가
- 검증: 상품 `Closed`, 투자자 수익권과 청구액, 역할별 mUSD 잔액 및 Bridge 부채 0 확인

## CRB-INT-005 — 최초 접속 시 스타일 미적용 화면 노출

- 상태: 해결
- 영향: 브라우저가 스타일 없는 초기 HTML을 먼저 표시하고 외부 CDN 장애 시 화면 스타일이 계속 적용되지 않을 수 있음
- 원인: Tailwind CSS를 빌드에 포함하지 않고 본문 뒤의 `@tailwindcss/browser` 런타임 스크립트로 생성
- 처리: Tailwind CSS v4 PostCSS 플러그인과 정적 전역 CSS 빌드 구성으로 전환
- 검증: 최초 HTML의 CSS 링크가 Tailwind 유틸리티를 포함한 로컬 번들을 가리키고 외부 런타임 스크립트가 제거됐는지 확인

## CRB-INT-006 — 페이지와 공통 화면 골격 결합

- 상태: 해결
- 영향: 헤더와 모바일 탐색이 메인 페이지에 직접 구현되어 다른 화면에서 재사용하거나 독립적으로 수정하기 어려웠음
- 처리: 브랜드·탐색·지갑 영역을 `Header`로 분리하고 저작권 정보를 포함한 `Footer` 추가
- 화면 구성: 콘텐츠 영역은 순백색으로 유지하고 기존 연회색 배경을 헤더와 푸터에 적용

## CRB-INT-007 — 운영 상품 catalog와 온체인 상품 부재

- 상태: 해결
- 문제: 백엔드는 단일 classpath JSON만 제공하고 프론트엔드는 조회 실패 시 코드에 포함된 목업 상품을 노출
- 처리: PostgreSQL과 Flyway 기반 상품·정산 기간 schema, 세 개의 초기 Base Sepolia 데모 상품, 상품 목록 API 구성
- 온체인: Base Sepolia `RevenueBridge`에 상품 ID `1`부터 `3`까지 등록하고 DB의 금액·일정 mirror를 실제 트랜잭션과 일치하도록 구성
- 데모 만기: 세 번째 상품에 환경 변수로 조절 가능한 단축 모집·수익·정산 기간 적용
- 보안: 운영 서버에는 배포 개인키를 저장하지 않고 개발 PC의 Foundry script에서 issuer 트랜잭션 실행
