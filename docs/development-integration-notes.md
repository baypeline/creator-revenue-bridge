# 개발 연동 기록

> 기준일: 2026-09-10
> 범위: 로컬 Anvil, 컨트랙트 배포, 프론트엔드·백엔드 연동

## CRB-INT-001 — 로컬 배포 후 거래 가능한 데모 상태 부족

- 상태: 해결
- 영향: 프론트엔드가 배포 직후 실제 투자·정산 흐름을 실행할 수 없었음
- 원인: 기존 배포 스크립트가 투자자에게만 mUSD를 지급하고 상품을 생성하지 않았음
- 처리: 별도 크리에이터 주소, 정산자 mUSD 잔액과 모집 중인 데모 상품 초기화 추가
- 검증: 배포 테스트와 Docker Anvil 상태 조회로 역할·잔액·상품 조건 확인

## CRB-INT-002 — 배포 주소와 ABI의 애플리케이션 공유 방식 부재

- 상태: 해결
- 영향: 프론트엔드에 하드코딩한 주소가 실제 배포 주소와 달라질 수 있음
- 처리: 로컬 배포 manifest 생성과 세 컨트랙트 ABI 추출을 하나의 명령으로 자동화
- 산출물: 프론트엔드와 백엔드의 생성 전용 컨트랙트 디렉터리에 동일한 주소·ABI 복사
- 후속 작업: 각 애플리케이션의 기존 하드코딩 설정을 생성 산출물 참조 방식으로 전환

## CRB-INT-003 — 프론트엔드 상품 상태와 컨트랙트 enum 불일치

- 상태: 해결
- 영향: 프론트엔드가 `Failed`, `Settling`, `Closed` 상태를 구분하지 못했음
- 처리: 컨트랙트 enum 값과 화면 표시 이름을 연결하는 공용 클라이언트 metadata 추가
- 추가 구성: 주요 custom error와 사용자 안내 메시지 매핑을 같은 metadata에 포함
- 검증: Foundry 테스트에서 여섯 개 상태 코드가 컨트랙트 enum 값과 일치하는지 확인

## CRB-INT-004 — 실제 RPC 전체 정상 흐름 자동화 부재

- 상태: 해결
- 영향: 애플리케이션 개발자가 역할별 호출 순서와 최종 잔액을 수동으로 검증해야 했음
- 처리: 새 데모 배포부터 투자·정산·종료·종료 후 청구까지 실행하는 단일 명령 추가
- 검증: 상품 `Closed`, 투자자 수익권과 청구액, 역할별 mUSD 잔액 및 Bridge 부채 0 확인
